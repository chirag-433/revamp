# 36-hour finale runbook

This is a rehearsal checklist. It does not assert that the finale date, event rules, team attendance, or required build-from-scratch policy are confirmed.

| Time | Objective | Exit check |
|---|---|---|
| Hours 0–1 | Set up local copy; check network; run demo path | Local copy works without network |
| Hours 1–4 | Read finale feedback and resolve critical defects | Defect owner and acceptance evidence for each fix |
| Hours 4–10 | Handle new matching cases and update measured results | Evaluation report saved with dataset version |
| Hours 10–16 | Polish Overlap Center, institution profile and accessibility | Keyboard path and comparison verified |
| Hours 16–22 | Verify reports, alerts and export | Files open and counts match the displayed filters |
| Hours 22–26 | Run end-to-end role checks and fix top defects | Demo path passes on the local copy |
| Hours 26–29 | Refresh final visuals and offline recording | Backup files open from a second location |
| Hours 29–30 | Freeze a known-good revision | Version tag and local reset completed |
| Hours 30–33 | Rehearse the presentation and likely questions | Timed result and open issues recorded |
| Hours 33–36 | Final equipment and data checks; rest in shifts | Presenter, driver and question owners know their roles |

## Cut order if time runs short

1. Cut Hindi labels, extra reports, and email alerts.
2. Cut embeddings and use the explainable local similarity fallback.
3. Cut conflict rules while retaining institution resolution and overlap review.
4. Cut live updates and keep the local page refresh path.
5. Keep institution resolution, the coordination alert, side-by-side review, case history, and dashboard KPIs.

## Presentation-day checklist

- Laptop, charger, display adapter, local database, and seeded synthetic data are ready.
- Offline recording, deck PDF/PPTX, and screenshots are available locally and on a second device.
- Demo data is reset; the noisy institution example is staged; required pages are open.
- The speaker order, screen driver, timekeeper, and technical question owners are assigned.
- The event's current rules have been checked for use of prepared code.
